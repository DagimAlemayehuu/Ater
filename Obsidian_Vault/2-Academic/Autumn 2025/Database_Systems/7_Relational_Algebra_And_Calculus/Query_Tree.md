# 1. Mental Model
Imagine you're a librarian, and someone asks you a complex question like "Find all books written by authors from France who published a book after 2000." You'd break this question into smaller parts, like finding French authors, then books published after 2000, and finally matching authors with their books. A query tree works similarly, representing a complex query as a tree-like structure of smaller, manageable parts.

# 2. Schema & Query Mechanics
A query tree is an abstract representation of a query, typically generated by the database's [[Query_Parser]] and then optimized by the [[Query_Optimizer]]. It consists of nodes representing [[Relational_Algebra]] operations such as selection, projection, and join. The root node of the tree represents the final result set, while leaf nodes represent access to base tables or indexes. The query tree is traversed, and operations are executed according to the [[Execution_Plan]] generated from it.

# 3. ACID Violations & Scaling Limits
When dealing with complex queries, the query tree can become deeply nested, leading to potential performance issues and increased risk of [[Deadlocks]] or [[Livelocks]]. If not properly optimized, the query tree can result in inefficient [[Table_Scans]], causing the database to violate [[Acid]] principles, specifically atomicity and consistency, under high concurrency. Furthermore, as the database scales, the query tree's complexity can lead to limitations in [[Horizontal_Scaling]], making it challenging to distribute query loads efficiently across multiple nodes.

## 5. Walkthrough
Suppose we have a database with two tables: `authors` and `books`. We want to find all books written by authors from France who published a book after 2000.

1. The query is parsed and a query tree is generated:
   - Root node: `result_set`
   - Child nodes: 
     - `selection` (authors from France)
     - `selection` (books published after 2000)
     - `join` (authors and books)

2. The query tree is optimized:
   - The `selection` nodes are reordered to reduce the number of rows being joined.

3. The optimized query tree:
   - Root node: `result_set`
   - Child nodes: 
     - `join` (authors and books)
       - `selection` (authors from France)
       - `selection` (books published after 2000)

4. The query tree is traversed, and an execution plan is generated:
   - Access the `authors` table and apply the selection (authors from France).
   - Access the `books` table and apply the selection (books published after 2000).
   - Join the results of the two selections.

5. The execution plan is executed, and the result set is returned.
