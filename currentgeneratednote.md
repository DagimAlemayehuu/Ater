# COMPANY Database Schema
## Context & Prerequisites
Understanding the [[COMPANY Database Schema]] is crucial for working through examples of [[Relational Algebra Introduction]] operations. Basic knowledge of the [[Relational Model]] including concepts like tables, attributes, primary keys, and foreign keys is assumed.

## Core Synthesis
The COMPANY database schema serves as a common example for illustrating relational algebra and other database concepts. It models a company's organizational structure and employee information.

*   **Relations (Tables) and their Attributes**:
    *   **EMPLOYEE**: Stores details about employees.
        *   Attributes: `Fname`, `Minit`, `Lname`, `Ssn` (Primary Key), `Bdate`, `Address`, `Sex`, `Salary`, `Super_ssn` (Foreign Key to EMPLOYEE.Ssn), `Dno` (Foreign Key to DEPARTMENT.Dnumber).
    *   **DEPARTMENT**: Stores details about departments.
        *   Attributes: `Dname`, `Dnumber` (Primary Key), `Mgr_ssn` (Foreign Key to EMPLOYEE.Ssn), `Mgr_start_date`.
    *   **DEPT_LOCATIONS**: Stores multiple locations for departments.
        *   Attributes: `Dnumber` (Foreign Key to DEPARTMENT.Dnumber), `Dlocation` (Composite Primary Key with Dnumber).
    *   **PROJECT**: Stores details about projects.
        *   Attributes: `Pname`, `Pnumber` (Primary Key), `Plocation`, `Dnum` (Foreign Key to DEPARTMENT.Dnumber).
    *   **WORKS_ON**: Records which employee works on which project and for how many hours.
        *   Attributes: `Essn` (Foreign Key to EMPLOYEE.Ssn), `Pno` (Foreign Key to PROJECT.Pnumber), `Hours` (Composite Primary Key with Essn, Pno).
    *   **DEPENDENT**: Stores details about employee dependents.
        *   Attributes: `Essn` (Foreign Key to EMPLOYEE.Ssn), `Dependent_name` (Composite Primary Key with Essn), `Sex`, `Bdate`, `Relationship`.
*   **Referential Integrity Constraints**: Displayed within the schema, indicating how relations are linked via foreign keys, ensuring data consistency.
